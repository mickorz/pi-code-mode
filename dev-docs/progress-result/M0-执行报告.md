## 2. 实证结果（spike.ts，真实模型）

实证环境：pi SDK `@earendil-works/pi-coding-agent@1.3.0`（与宿主 CLI 1.3.0 对齐）、模型 `glm-5.3-flash`（Zhipu）、子会话 `SessionManager.inMemory()` + `SettingsManager.create` 继承用户认证。

| 用例 | 结果 | 关键数据 |
|---|---|---|
| execute-text | PASS | 基础链路 1.8-2.5s；**usage 为规范化单值** `{input, output, cacheRead, cacheWrite, reasoning, totalTokens, cost}` 直接挂在 assistant message 上 |
| execute-cancel | PASS | `session.abort()` 后 **13ms** 到 `agent_settled {aborted:true}`；取消快速生效 |
| execute-timeout | PASS | Engine 侧计时超时复用 abort 通道，与 cancel 同机制（契约 §3.2 成立） |
| tools-none | PASS | `noTools:"all"` + `excludeTools:["*"]` 后模型自认 NO-TOOLS，零工具调用 |
| tools-wildcard | PASS | `excludeTools:["bash*","edit*","write*"]` 通配符精确禁用 |
| recursive-guard | PASS | `DefaultResourceLoader({noExtensions:true})` 下宿主扩展**零加载**（本机装有 pi-dynamic-workflows 等大量扩展均未加载）——递归编排通道关闭 |
| structured-basic | PASS | prompt 要求 JSON 透传可行（P0 层级；typebox 校验+修复循环属 M2） |

完整原始输出见 `dev-examples/m0-spike/`（重跑：`npx tsx spike.ts`）。

## 3. 契约测试结果（contract.test.ts，零 LLM）

7/7 PASS：ok 形态完整、cancelled/timeout usage 缺省不冒充 0、error kind 归类、cancel 幂等且未知 id 静默、executionId 由 Engine 生成原样到达、在途取消返回 cancelled 终态、Engine 计时超时收尾。这套断言即 M1 `PiAgentAdapter` 的验收靶子（重跑：`npx tsx --test contract.test.ts`）。

## 4. Go/No-Go 判定：**GO**

| 判定项 | 结论 |
|---|---|
| execute/cancel/timeout 三原语 | 全部实证可用，语义与契约一致 |
| 工具权限与递归防护 | SDK 原生 `excludeTools`（含通配符）+ `noExtensions` 双保险均实测生效 |
| usage | pi 已规范化单值，无 opencode step-finish 覆盖问题，Adapter 直取 |
| Engine 宿主无关性 | opencode runtime 四模块（VM/DSL/Composite/Worktree）审计确认无宿主耦合，journal 结构可复用（key 语义按契约 §3 分阶段） |
| 契约测试就绪 | Mock Adapter + 7 断言固化，M1 实现即有靶 |

**结论：现有 OpenCode Workflow Runtime 可以通过最小的 AgentAdapter 改造在 pi 中保持一致的执行语义。M1 启动。**

## 5. 关键发现与遗留（输入 M1/M2）

1. **checkpoint 的 ask 原语不存在**（审计 §6 风险被证实）：pi SDK 无 canUseTool/permission 通道（headless）。M2 的 `checkpoint()` 需自定义通道（自定义等待确认工具 / 宿主 TUI 层事件），在此之前按契约 §3.4 headless 默认值。**遗留至 M2 设计。**
2. **usage 形态确认**：`usageRaw = message.usage` 单值；「取消时 usage 部分返回」实测存在（execute-cancel 返回了 1 条带 usage 的消息）——Adapter 按「非 ok 终态缺省」处理即可，契约 §2 已覆盖。
3. **模型指定**：settings 默认模型链路可用；显式 `model: Model<any>` 参数存在（`getModel(provider, id)`），M4 tier 体系实现时对接。
4. **M1 实现顺序建议**：package 骨架 → PiAgentAdapter（以 contract.test.ts 为靶）→ runtime 移植（VM/DSL 先行，journal 按 M1 序号制基线）→ workflow 工具注册 → P0-A 验收。
