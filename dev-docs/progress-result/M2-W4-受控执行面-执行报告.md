# M2-W4-受控执行面（路线 A）-执行报告

> 阶段：M2-W4（路线 A：沙盒无法承载的命令走受控宿主执行）
> 日期：2026-11-25
> 前置：M2-W3b（实测结论：GUI Electron 无法在 MXC BaseContainer 内启动）
> 结果：**E2E 6/6 PASS；contract +10（302 total / 0 fail）；engine 222/0**

## 1. 背景

M2-W3b 实证：`CocosCreator.exe`（Electron GUI）在 MXC BaseContainer 内**无法启动**（`dir` 枚举与 exe 启动均"拒绝访问"，加 `writePaths`/`--no-sandbox`/`--disable-gpu` 均无效）——这是 MXC 的隔离设计，不是权限不足。

因此 `cocoscli build` 这类 GUI 构建链不能作为沙盒内命令。用户选择**路线 A**：构建走沙盒外的受控执行面。

## 2. 四条硬约束（实现要点）

| 约束 | 实现 |
|---|---|
| **分类不由模型决定** | 规则只从项目配置文件 `.pi/workflows/control-plane.json` 读取（`loadControlPlaneRules`）；模型在 `run_command` 参数里无法声明"请用控制面执行" |
| **必须显式审批** | `request.approve`（受控工具注入，走 `ctx.ui.confirm`）> `options.approve`（宿主配置）> 都没有则拒绝。print/headless 无 UI → 自动 fail-closed |
| **全程审计** | 每条请求（含被拒）回调 `onAudit`，记命令/cwd/规则 reason/决策/退出码/耗时/runId/executionId；**不记输出内容**（A4 有断言） |
| **绝不静默降级** | `RoutedCommandExecutor` 在调用前决定路由；沙盒失败**不会**触发控制面。A3b 断言：未命中规则的 GUI 命令沙盒失败后控制面调用次数 = 0 |

## 5. 需要的配置（生效方式）

```bash
cp .pi/workflows/control-plane.example.json .pi/workflows/control-plane.json
# 按实际命令形态调整 match（当前为 `index.js build` / `CocosCreator.exe`）
```

未配置时：控制面规则为空 → 所有命令走沙盒 → GUI 构建命令被 fail-closed 拒绝（不会悄悄用宿主跑）。

## 6. 安全边界（诚实声明）

- **控制面命令在宿主执行，不受 MXC 隔离**。这是明确的取舍：GUI 构建链无法隔离。因此审批提示必须让用户看清 cwd 与完整命令（已在 `ctx.ui.confirm` 中展示前 400 字符）。
- **规则是项目级配置**：恶意修改 `.pi/workflows/control-plane.json` 可扩大控制面范围。该文件应纳入代码评审（与 `.pi/settings.json` 同级的信任面）。
- 审批在 print/headless 模式不可用 → 定时任务（routines）中的 GUI 构建**无法执行**，属预期 fail-closed 行为。
- 审计目前只回调 `onAudit`（插件入口暂未落盘）；落盘到 workflow journal 属后续接线。

## 7. 遗留

| 项 | 说明 |
|---|---|
| 审计落盘 | `onAudit` 已就绪，插件入口尚未写入 journal/日志文件 |
| 规则粒度 | 当前为子串/正则匹配命令文本；更严格的"构建命令分类器"留待需要时 |
| Windows Sandbox 正式验收 | 仍为 CONDITIONAL；本次是"无法承载的部分有了明确出路"，不等于整体放行 |
| 沙盒内 GUI 可行性 | 结论为不可行（MXC 设计），若将来 Cocos 提供 headless 再评估 |
