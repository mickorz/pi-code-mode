# M2-W4-受控执行面（路线 A）-执行报告

> 阶段：M2-W4（路线 A：沙盒无法承载的命令走受控宿主执行）
> 日期：2026-11-25
> 前置：M2-W3b（实测结论：GUI Electron 无法在 MXC BaseContainer 内启动）
> 结果：**E2E 6/6 PASS；contract +10（302 total / 0 fail）；engine 222/0**

## 1. 背景

M2-W3b 实证：`CocosCreator.exe`（Electron GUI）在 MXC BaseContainer 内**无法启动**（`dir` 枚举与 exe 启动均"拒绝访问"，加 `writePaths`/`--no-sandbox`/`--disable-gpu` 均无效）——这是 MXC 的隔离设计，不是权限不足。

因此 `cocoscli build` 这类 GUI 构建链不能作为沙盒内命令。用户选择**路线 A**：构建走沙盒外的受控执行面。

## 2. 四条硬约束（实现要点）

| 约束 | 实现 |
|---|---|
| **分类不由模型决定** | 规则只从项目配置文件 `.pi/workflows/control-plane.json` 读取（`loadControlPlaneRules`）；模型在 `run_command` 参数里无法声明"请用控制面执行" |
| **必须显式审批** | `request.approve`（受控工具注入，走 `ctx.ui.confirm`）> `options.approve`（宿主配置）> 都没有则拒绝。print/headless 无 UI → 自动 fail-closed |
| **全程审计** | 每条请求（含被拒）回调 `onAudit`，记命令/cwd/规则 reason/决策/退出码/耗时/runId/executionId；**不记输出内容**（A4 有断言） |
| **绝不静默降级** | `RoutedCommandExecutor` 在调用前决定路由；沙盒失败**不会**触发控制面。A3b 断言：未命中规则的 GUI 命令沙盒失败后控制面调用次数 = 0 |

## 6. 安全边界（诚实声明）

- **控制面命令在宿主执行，不受 MXC 隔离**。这是明确的取舍：GUI 构建链无法隔离。因此审批提示必须让用户看清 cwd 与完整命令（已在 `ctx.ui.confirm` 中展示前 400 字符）。
- **规则是项目级配置**：恶意修改 `.pi/workflows/control-plane.json` 可扩大控制面范围。该文件应纳入代码评审（与 `.pi/settings.json` 同级的信任面）。
- 审批在 print/headless 模式不可用 → 定时任务（routines）中的 GUI 构建**无法执行**，属预期 fail-closed 行为。
- 审计目前只回调 `onAudit`（插件入口暂未落盘）；落盘到 workflow journal 属后续接线。

## 8. 审计落盘（M2-W4b，2026-11-25 收尾）

### 8.1 为什么不用 run journal

`run journal` 的语义是"**按 run 一次性写终态快照**"（`.pi/workflows/journal/run-*.json`，字段 version/runId/entries）。
控制面审计需要的是"**逐事件追加**"，且包含跨 run 的决策（如未进入任何 run 的拒绝）。
两者性质不同，塞在一起会破坏 journal 的快照语义，因此新建独立的追加式日志。

### 8.2 交付

| 文件 | 职责 |
|---|---|
| `packages/execution/src/audit/control-plane-audit.ts` | `ControlPlaneAuditWriter`：append-only JSONL，按日分文件，串行化写队列 |
| `apps/plugin/extensions/pi-code-mode.ts` | 装配 `onAudit → writer.write` |
| `tests/contract/control-plane-audit.test.ts` | 5 用例 |

**落盘位置**：`.pi/workflows/audit/control-plane-YYYY-MM-DD.jsonl`（按本地日期分文件，便于轮转与按天排查）

**记录形态**（一行一事件）：

```json
{"at":1795599857584,"command":"...","cwd":"...","rule":"GUI 构建链无法在 MXC 内启动","decision":"approved","exitCode":0,"durationMs":39000,"runId":"run-audit","executionId":"exec-audit","ts":"2026-11-27T01:44:27.584Z","kind":"control-plane"}
```

### 8.3 三个设计取舍

1. **append-only 而非改写**：并发安全、崩溃不丢已写记录、可直接 `grep`/`jq` 消费。
2. **只记事实**：命令文本、cwd、规则理由、决策、退出码、耗时、runId/executionId。**不含 stdout/stderr**（event 结构本身就没有这两个字段，测试 A4 额外断言落盘文本不含）。
3. **写失败不阻断执行**：审计是旁路，不是执行前提。磁盘异常只警告**一次**（避免刷屏），命令结果不受影响 —— 若反过来，磁盘问题会变成执行故障。

### 8.4 验证

contract（新增 5 例）：AUD-01 按日分文件 / AUD-02 append 不覆盖 / AUD-03 50 条并发写不交错且全部合法 JSON / AUD-04 不含输出内容 / AUD-05 写失败只警告一次且不 reject。

**端到端（真实构建）**：`.pi/workflows/audit/control-plane-2026-11-27.jsonl` 实录两行

```
2026-11-27T01:43:48.609Z | denied   | exit=- | no_approval_channel
2026-11-27T01:44:27.584Z | approved | exit=0 | GUI 构建链无法在 MXC 内启动 | runId=run-audit
```

拒绝路径与批准路径**都被记录**，且不含输出内容。
