## 2. 关键设计（对应评审三处细节）

### 2.1 一命令一 Host 进程

SRT 的 `SandboxManager` 是模块级单例，配置/代理/运行时资源都挂在模块状态。同进程包裹两条不同权限的命令会互相污染。故每条命令 spawn 一个独立 Host 进程 → 独立 SRT Runtime → 独立 allowlist 与代理。S8 场景（并行命令配置不串扰）即验收此项。

### 2.2 SRT 的 abortSignal ≠ 子进程取消

`wrapWithSandbox(command, shell, config, abortSignal)` 的 abortSignal 只覆盖**包裹阶段**。正在运行的子进程必须由 Host 自己终止。实现：

```
abort/timeout -> kill(-hostPid, SIGTERM) -> 3s 宽限 -> SIGKILL -> 等 Host 退出 -> drain stdout/stderr
```

Host 以 `detached: true` spawn 成为进程组长，命令与其派生进程同组 → 杀组即杀全部。Host 退出前还会轮询 `groupMemberCount()`，残留则 SIGKILL（应对 `server &` 类命令）。父进程死 → Host 的 stdin EOF → 同样杀组。

### 2.3 cwd 与路径

- Host 直接以 `cwd: payload.cwd` spawn（**不用 `process.chdir()`**），SRT 相对路径语义依赖实际进程 cwd。
- 配置层全部生成**规范化绝对路径**（`normalizeAbsolute`：resolve + realpath），且 `literal: true` 避免 macOS/Linux glob 语义差异（Linux 的 allowWrite/denyWrite 用具体路径）。

### 2.4 Windows 明确拒绝

`createCommandExecutor()` 在 win32 返回 `UnavailableCommandExecutor`，`SrtCommandExecutor` 自身也有平台短路。**不依赖 SRT 的 `isSupportedPlatform()`**——0.0.81 的 Windows Alpha 后端对 windows 也返回 `true`，但本项目隔离承诺只为 darwin/linux 背书。

## 5. 已知边界与后续

- **M2.2 网络白名单注入**：当前 `SrtCommandExecutor` 用默认空 allowlist（全拒）。按命令注入白名单需在 M2.2 接策略层 → `policy.allowedDomains` 参数已就位（`SandboxPolicyInput`），只需从 `SandboxCommandRequest` 透传。S4b 目前断言的是"非白名单仍被拒绝"。
- **M2.2 读取限制**：SRT 默认允许读取，当前只 deny 凭据目录。是否进一步收紧（如仅允许工作区读）需按实际命令可用性权衡，M2.2 定。
- **中间目录 TOCTOU 残留**：FileService 侧仍未解决（Node 无 openat），M2 沙盒只约束子进程。已在 M1.2 注释声明，不视为已解决。
- **SRT 依赖检查**：Linux 需 `ripgrep` 与 seccomp helper；缺失时 Host 报 `failed 125` → 父进程返回 `isolation_unavailable`（fail-closed，不降级）。打包分发成本待 M2.4 评估。
