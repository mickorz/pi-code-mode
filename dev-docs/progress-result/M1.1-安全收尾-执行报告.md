## 2. TOCTOU 防护方案（P1 专项）

`packages/execution/src/files/path-boundary.ts` 新增 `openWithin(root, target, mode)`：

1. **边界**：canonicalize（realpath 消解 symlink）后必须落在 root 内。
2. **最终组件 symlink 拒绝**：lstat 判定；create 模式用 `"wx"`（O_CREAT|O_EXCL，内核不跟随最终 symlink）。
3. **fd 复核**：打开后 `fstat(fd)` 与 lstat 的 dev+ino 比对，不一致 = 检查后被替换，拒绝。
4. **fd 化 IO**：WorkspaceFileService 全部从 FileHandle 读写（`write(data, 0, "utf8")` 显式 position），打开后不再走路径解析。

**残余风险（如实声明，写进源码注释）**：中间目录整链在检查后（T1）与内核 open（T2）之间被替换的窗口仍在（Node 无 openat）。缓解：M2 后 run_command 在沙盒内（可写边界=工作区），与"FileService 拒绝 symlink 最终组件"共同收窄攻击面；OS 级完整隔离依赖 M2 SRT。

## 3. 过程中抓到并修复的真 bug

fd 化后 `edit`（读后写同一 fd）从 fd 尾部追加内容（`'hello worldgo'`）——`FileHandle.readFile` 把 position 推到尾部，`writeFile` 从当前位置写。修复：`handle.write(next, 0, "utf8")` + truncate。坑位沉淀：`dev-docs/experience/filehandle-write-after-read-appends-at-position.md`。**该 bug 由 contract 测试的 roundtrip 断言抓出——fd 化文件服务必须配写-读-改-读回测试。**
