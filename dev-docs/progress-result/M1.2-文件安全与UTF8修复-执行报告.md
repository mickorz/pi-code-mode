# M1.2-文件安全与 UTF-8 修复-执行报告.md

> 阶段：M1.2（M1.1 评审后的最后修复批次，M1 冻结前置）
> 日期：2026-11-25
> 前置：M0 / M0.1 / M1 / M1.1

## 1. 背景

M1.1 评审确认主体完成，但代码复核发现两个必须修复的问题，M1.1 安全收尾暂不能视为完全通过：

| 问题 | 级别 | 实质 |
|---|---|---|
| openWithin 的 inode 复核无效 | P0 | 比对 `fstat(fd)` 与**打开后**的 `stat(real)`：攻击者替换后两侧都是外部文件，校验恒通过，形同虚设 |
| write/edit 用 `content.length` truncate | P1 | `content.length` 是 UTF-16 码元数，truncate 收字节数——中文/Emoji 内容被截断 |

## 2. 修复内容

### P0：openWithin inode 复核（三层改为真正有效）

`packages/execution/src/files/path-boundary.ts`：

1. **打开前 lstat 保存**：`before = lstat(real)`，最终组件 symlink 即拒绝。
2. **O_NOFOLLOW 内核层拦截**（Linux/macOS）：`open(real, baseFlags | O_NOFOLLOW)`。T1..T2 窗口内目标被换成 symlink 时，内核直接 `ELOOP` 失败（`symlink_race_blocked`），不是事后才检查。Windows 无该语义（`O_NOFOLLOW = 0`，file symlink 本需特权），靠第 3 层。
3. **fstat 与「打开前 lstat」比对**（M1.2 核心修正）：`opened.dev/ino !== before.dev/ino` → `replaced_after_check` 拒绝。
4. create 模式 `O_CREAT|O_EXCL|O_WRONLY`：最终组件是 symlink 时内核不跟随。

**残余风险（源码注释如实声明）**：中间目录整链在 T1..T2 被替换的窗口仍在（Node 无 openat）。**并明确写明：SRT 只约束子进程，不保护宿主进程内的 WorkspaceFileService**——不能指望 M2 自动解决本服务的问题。

### P1：UTF-8 字节正确性

`packages/execution/src/files/workspace-file-service.ts`：

```ts
const buffer = Buffer.from(content, "utf8")
await handle.write(buffer, 0, buffer.length, 0)   // 显式 position 0（fd 当前位置不可信）
await handle.truncate(buffer.length)              // 字节长度，不是 content.length
```

write 与 edit 两处均改。

### 测试加强（真正的竞争窗口）

新增 `OpenWithinHooks.beforeOpen` 注入点（生产不传），在 lstat 之后、open 之前确定性地模拟攻击：

- **symlink 替换竞争**：`beforeOpen` 中删掉目标并建指向外部的 symlink → 断言 reason 必须是 `symlink_race_blocked`（证明被内核层拦截，而非走到事后检查）。
- **普通文件替换竞争**：`beforeOpen` 中 `rename` 覆盖目标（inode 变化，跨平台可跑）→ 断言 `replaced_after_check`。
- **UTF-8 三类内容**：中文 / Emoji / 混合 Markdown，写入读回一致 + 磁盘字节数 = `Buffer.byteLength`。
- **UTF-8 编辑两向**：变短（旧内容更长，验证 truncate 字节）、变长（中文换 Emoji）。

## 5. 结论与下一步

M1/M1.1/M1.2 至此冻结。安全边界状态：

- 可绕过 Tool Gateway 的执行路径：无（M1.1 已封闭 extraTools/noExtensions）。
- 最终组件 symlink 替换：内核 O_NOFOLLOW + inode 复核双保险（Linux/macOS 全效，Windows 靠 inode 复核）。
- 中间目录整链替换：**已知残余风险**，Node 无 openat 无法根治；M2 沙盒收窄命令侧攻击面，但宿主侧 FileService 不被 SRT 覆盖（已注释声明）。
- UTF-8：字节级正确，中文/Emoji 内容安全。

下一步 M2 Sandbox Execution：Mac mini 首验 SRT Seatbelt、Linux 补 bubblewrap+seccomp、Windows 显式 `isolation_unavailable`、AbortSignal/超时/进程组终止/无孤儿进程、一命令一 Sandbox Host 并行隔离。
