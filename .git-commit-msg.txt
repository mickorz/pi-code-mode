feat(optimize): review 说明每个选中簇的处理情况（选中几个 / 处理几个 / 未处理的为什么）

问题：实测选中 4 个簇（IO-001/RETRY-001/DET-001/REC-002）却只改了 1 处，
review.md 完全没说另外 3 个为什么没动，读者会以为被静默丢弃。

改动：
- ReviewInput 增加 clusterOutcome（ruleId + handled/skipped/needs-human + reason）
- review-renderer 每个簇标题后标状态徽标，未处理/待人工的显示「说明」行，
  并在段落末尾给汇总一行：「选中 N 个簇：已处理 M / 未处理 K / 待人工 J」
- optimize 生成 clusterOutcome：补丁里有该 ruleId 的 edit = handled；
  有补丁但没这个规则 = skipped（本轮只改 1 个文件的预算限制）；
  完全没补丁 = needs-human（模型判定不可自动改）

pi -p 端到端验证（dev-examples/apply-e2e 造 2 簇 fixture：RETRY-001 + IO-001）：

  ### IO-001（1 处，low，置信度 0.80）— 未处理
  - 说明：本轮只改 1 个文件（输出预算与超时限制），该簇需下一批次单独跑 optimize
  ### RETRY-001（1 处，low，置信度 0.80）— 已处理
  **选中 2 个簇：已处理 1 / 未处理 1 / 待人工 0**

真实大脚本（1-scan-template.js，4 簇）同款输出已验证。
